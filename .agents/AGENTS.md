# CampusHub Feature Justification & Minimalist Product Rules

Every new feature considered or proposed for CampusHub MUST strictly justify its existence before implementation.

## Feature Evaluation Criteria

Before implementing ANY feature, evaluate and answer the following four questions:

1. **What student problem does this solve?** (Must address a real, everyday college student friction point).
2. **How often will a student use it?** (Must be useful daily or weekly, not a rare gimmick).
3. **Is this essential for the MVP?** (Must be strictly required for the core 8 modules: Dashboard, Timetable, Attendance, Assignments, Notes, Placements, Profile, Settings).
4. **Can this be done in a simpler way?** (Always prefer the simplest, most friction-free implementation).

## Core Directives

- **If any answer is "No"**, DO NOT implement the feature.
- **Prefer removal over addition**: Actively purge non-essential widgets, decorative fluff, complex settings, and enterprise bloat.
- **Keep text human & simple**: No marketing buzzwords, exaggerations, or fake complexity.
